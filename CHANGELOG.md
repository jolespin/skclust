# Change Log
* [2026.6.19] - **Breaking change**: replaced `cut_method='dynamic'` with `cut_method='hybrid'` and `cut_method='tree'` in `HierarchicalClustering` to match the two algorithms in the R `dynamicTreeCut` package. The R package's `cutreeDynamic` is just a wrapper that dispatches to `cutreeHybrid` (dendrogram + distance matrix + PAM) or `cutreeDynamicTree` (dendrogram only) — there is no distinct "dynamic" algorithm. `'dynamic'` is no longer accepted; valid `cut_method` values are `'hybrid'`, `'tree'`, `'height'`, and `'maxclust'`.
* [2026.6.19] - **Breaking change**: changed `HierarchicalClustering` defaults to match the R `dynamicTreeCut` package — `min_cluster_size` 3→20, `deep_split` 2→1.
* [2026.6.19] - Added hybrid-specific PAM parameters to `HierarchicalClustering`: `pam_stage` (default `True`), `pam_respects_dendro` (default `True`), `use_medoids` (default `False`), `max_pam_dist` (default `None` → `cutHeight`), `respect_small_clusters` (default `True`). All defaults match the R `dynamicTreeCut` package.
* [2026.6.19] - `deep_split` is now automatically coerced between int and bool when switching between `cut_method='hybrid'` (int 0–4) and `cut_method='tree'` (bool), with an info-level log message. This supports parameter sweeps across cut methods without raising errors.
* [2026.6.18] - **Breaking change**: removed `outlier_cluster` parameter from `HierarchicalClustering`. Outliers from `dynamicTreeCut` are now always labeled `-1` (or `"Outlier"` when `cluster_prefix` is set) and cluster indices start at `0`. Added `outliers_` (list of outlier sample labels) and `n_outliers_` attributes.
* [2026.6.18] - Fixed `dynamicTreeCut` outlier handling in `HierarchicalClustering` — outlier label `0` from `cutreeHybrid` was not being distinguished from real clusters. Labels are now shifted by `-1` so outliers become `-1` and clusters start at `0`.
* [2026.6.18] - Added `outlier_label` parameter to `HierarchicalClustering.plot()` — controls the display label for outlier samples in the cluster track (default `None` → empty string).
* [2026.6.18] - Fixed NumPy 2.0 compatibility for `dynamicTreeCut` in `HierarchicalClustering` by patching removed `np.in1d` with `np.isin` during dynamic tree cutting
* [2026.6.18] - **Breaking change**: changed default linkage method in `HierarchicalClustering` from `'ward'` to `'average'`
* [2026.6.18] - **Breaking change**: `HierarchicalClustering.fit()` now raises `ValueError` when input appears to be a precomputed distance matrix (square, symmetric, zero diagonal) or is a skbio `DistanceMatrix` but `metric='precomputed'` is not set
* [2026.6.18] - **Breaking change**: `distance_matrix_` is now stored as a skbio `DistanceMatrix` instead of a `pd.DataFrame`. Access the underlying numpy array via `.data` and sample IDs via `.ids`. Use `.to_data_frame()` to convert back to a DataFrame.
* [2026.6.18] - Added `title`, `track_padding`, and `outlier_color` parameters to `HierarchicalClustering.plot()`
* [2026.6.18] - Added `to_igraph()` method to `HierarchicalClustering` — converts the fitted distance matrix to a weighted undirected igraph graph with node labels from sample labels and cluster assignments as vertex attributes. Supports optional `threshold` parameter for edge filtering.
* [2026.6.18] - Added support for skbio `DistanceMatrix` as direct input to `HierarchicalClustering.fit()`
* [2026.6.18] - Made `fastcluster` and `skbio` required dependencies with top-level imports in `skclust.hierarchical`
* [2026.6.17] - **Breaking change**: removed the `consensus_threshold` parameter from `ConsensusLeidenClustering`; consensus is now always unanimous (all iterations agree). Results are unchanged since the default was already `1.0`, but the parameter is gone because any value below `1.0` silently degraded into single-linkage clustering on the co-association matrix.
* [2026.6.17] - **Breaking change**: `resolution_parameter` is now passed to any partition type whose constructor accepts it (e.g. `CPMVertexPartition`), not only `RBConfigurationVertexPartition`. CPM previously ran at its internal default resolution regardless of the supplied value, so this changes CPM clustering results.
* [2026.6.17] - **Breaking change**: renamed the `modularity_` attribute to `quality_` and generalized it to report the optimized objective (CPM, modularity, significance, surprise, …) instead of always modularity. Keys are `initial` and `filtered`; the consensus-graph value (≈1.0 by construction) was dropped.
* [2026.6.17] - **Breaking change**: renamed the per-iteration matrix export to its complement and made it opt-in — `store_membership_matrix` / `membership_matrix_` / `get_membership_matrix()` are now `store_disagreement_matrix` / `disagreement_matrix_` / `get_disagreement_matrix()` (`True` = endpoints in different clusters). It is no longer built by default, and is genuinely sparse for high-consensus data where the co-membership matrix was mostly `True`.
* [2026.6.17] - **Breaking change**: `summary_` keys renamed — `modularity_*` → `quality_*` and `consensus_ratio_before_filter` → `mean_consensus_ratio` (same value) — and `consensus_std_before_filter` plus the `pct_100`/`pct_90plus`/…/`pct_below_50` percentile ladder removed. `summary_` is now `object` dtype (was `float64`) because it carries string fields, which breaks any downstream `summary_.astype(float)`.
* [2026.6.17] - **Breaking change**: removed the public `leiden_stability()` function (its metrics are folded into `summary_`) and the public `cluster_membership_cooccurrence()` function (replaced by an internal O(n_edges) accumulator; its dead all-pairs branch is gone).
* [2026.6.17] - **Breaking change**: dropped `TransformerMixin` from `ConsensusLeidenClustering` (now `BaseEstimator, ClusterMixin`); `transform`/`fit_transform` still return labels and `get_feature_names_out()` still returns `consensus_edges_`.
* [2026.6.17] - Changed the default `n_iter` in `ConsensusLeidenClustering` from 100 to 10. Note this is a weaker consensus filter, since fewer iterations make unanimity easier to reach; `ClusteredNetwork` passes `n_iter=1000` explicitly and is unaffected.
* [2026.6.17] - Fixed `consensus_edges_` ordering to use a canonical, input-order-independent sort; the previous `sorted()` over `frozenset` objects was a no-op and only accidentally deterministic.
* [2026.6.17] - Added `summary_` fields `ratio_stable_edges` (unanimous-edge fraction, matched pair with `ratio_stable_nodes`), `partition_type`, `quality_metric`, `resolution_parameter` (the γ actually used; `NaN` for objectives that ignore it), and `pielou_evenness` (cluster-size balance via Shannon entropy; `NaN` for fewer than 2 clusters).
* [2026.6.17] - Added `cluster_sizes_` attribute to `ConsensusLeidenClustering` (`labels_.value_counts()`, largest-first).
* [2026.6.17] - Reimplemented consensus computation as a single O(n_edges) pass instead of materializing a dense `(n_edges × n_iter)` boolean matrix, fixing out-of-memory failures on large graphs with high `n_iter`. Vectorized igraph access, workers now return `partition.membership` directly, and `partitions_` is stored as `int32`.
* [2026.6.17] - `ConsensusLeidenClustering.__init__` now stores `leiden_kws` unchanged (resolved in `fit`) so `clone()` / `get_params()` round-trip cleanly.
* [2026.6.17] - Added `kneighbors_to_snn_graph` to `skclust.neighbors` to build Jaccard-weighted Shared Nearest Neighbor (SNN) graphs from KNN indices
* [2026.6.17] - Fixed automatic index attribute storing when using `pd.DataFrame` on `KNeighborsCosineSimilarity`
* [2026.6.5] - Added `skbio` as a required dependency
* [2026.6.5] - Removed `clustered_cosine_distances` and `clustered_jaccard_distances` in place of `skclust.distance.ClusteredDistances`, `pairwise_cosine_distances`, and `pairwise_jaccard_distances`
* [2026.6.3] - Updated `clustered_cosine_distances` and added `clustered_jaccard_distances`
* [2026.5.27] - Added `cosine_distances_to_representatives` to `skclust.distance` — computes cosine distances from each observation to its group's representative embeddings (e.g., core/union centroids). Supports multiple representative types per group, returns a `DataFrame` with one column per type. Includes `pandas/numpy` type concordance checks and index alignment validation consistent with `clustered_cosine_distances`.
* [2026.5.27] - Added `skclust.metrics.clustered_cosine_distances` for computing intra-cluster and inter-cluster cosine distance summaries from L2-normalized embeddings. Returns per-cluster median, mean, std, MAD, and number of pairs as a MultiIndex DataFrame. Supports chunked matrix multiplication for large datasets via `chunk_size` parameter.
* [2026.5.11] - Updated `eta_squared_score` with `method` parameter supporting `"trace"` (variance-weighted, Calinski-Harabasz style) and `"per_feature"` (equal-weighted) computation. Added input validation to `cv_score` with `checks` and `atol` parameters to flag non-positive values and near-zero means.
